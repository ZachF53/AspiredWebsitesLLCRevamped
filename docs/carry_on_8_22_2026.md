Written to hand this session to a laptop mid-thought. Read top to bottom;

Session covered: auditing the existing outreach system, migrating to

## The finding that reframes everything

**416 cold emails have gone out from prod. They have produced zero
replies from a human being.**

The 10 `EmailReply` rows in the database are not replies. Every one is
from `hello@aspired-ai.com` — Zach's own company — and they are Google
Ads budget notifications that IMAP ingest scooped up and filed against a
`Lead` row that happens to carry that address:

```
firm='Aspired AI LLC'  classification=wrong_person
  "Progress toward the $1,000 credit: estimated ~$494.16 of $500
   spent (99%). Need $5.84 more before Aug 16..."
```

Earlier in this session I told Zach the reply rate was 2.4% and therefore
normal, and that the only problem was volume. **That was wrong.** The
rate is 0/416. Volume is not the problem and scaling the current system
would make things actively worse.

I also said "the Apollo actor you already use." He has never used it — I
tested that actor this session and conflated it with his history. His
leads are `google_maps` (211) and `contact_form` (35).

### Verified prod numbers (2026-08-22)

```
EmailSent    416 sent, 7 rejected, 423 total — all kind='cold'
EmailReply   10 — all from his own domain, all junk
Lead         246 total — google_maps 211, contact_form 35
             ALL 246 still status='new' (pipeline never advanced them)
Sends        first 2026-05-31, last 2026-08-01  → nothing for 3 weeks
```

### Why it produced zero

Who the 416 emails actually went to:

| Mailbox pattern | Count |
|---|---|
| `info@` | 111 |
| `hello@` / `office@` / `lawassistant@` | 24 |
| consumer (gmail / yahoo / hotmail / aol / outlook) | 97 |
| obvious garbage — `user@`, `rohtopharmacy5@`, `macintosh.christa95@` | — |

**~56% went to a role mailbox or a personal gmail.** No decision-maker
reads `info@`, and role addresses are a common spam-trap pattern that
damages sender reputation on the way to being ignored.

The garbage addresses come from `enricher.py` scraping whatever email
string it finds on the page. `rohtopharmacy5@` was collected during a law
firm scrape.

**Root cause: the system sources businesses, not people.** Google Maps
returns a place. A place has a `info@` inbox. A person-level B2B database
returns a named partner with a work address. That single substitution is
the whole fix.

## Routes tested this session and rejected, with evidence

Keep this section so these don't get proposed again.

| Route | Result | Cost |
|---|---|---|
| **No-website businesses via Google Maps → Facebook → email** | 34 no-website businesses, 88% had a findable FB page, but **50% mismatch rate** on phone-verifiable matches. Only **20%** yielded a verified email; 12% a non-consumer one. **$0.063 per emailable lead.** | $0.44 |
| **Apollo-style DB for no-website businesses** | Structurally impossible. 27/100 had a blank `company_website`, but **11 of 13** distinct domains had live sites. Blank = missing data on franchise/branch records, not absence of a website. | — |
| **Texas Bar directory scraper** | Returns literal `"email": "(available via profile)"`. 0/5 real emails. | $0.20 |
| **`code_crafter/leads-finder` via API** | Refuses API runs on the free Apify plan. Bills the $0.02 start event, reports SUCCEEDED, writes one `{"error": ...}` row. Detection built (`_raise_if_actor_refused`). | $0.02 |

**Apify budget used: $0.96 of $5.**

What *did* work: `compass/crawler-google-places` runs fine on the free
plan and `website: withoutWebsite` genuinely filters. And the
Apollo-style actor returned emails for **98/98** leads at ~$0.0022 each
— that's the sourcing quality target.

## Sending infrastructure

### What exists

12 Instantly mailboxes, Gen-2, health 100%, ~60 warmup emails each:

```
zach.long@ / zach@ / zacherylong@ / zachlong@
  × getaspiredautomations.com
  × goaspiredautomations.com
  × seeaspiredautomations.com
```

That's ~360 sends/day of capacity. The infrastructure is real.

### The problem

Those are **Aspired Automations** domains. Sending website-design pitches
from `zach@getaspiredautomations.com` with a link to
`aspiredwebsites.com` is a brand mismatch a prospect clocks instantly —
it reads as bait-and-switch, and any spam complaints it earns burn the
Automations brand those mailboxes were built for.

### The move

Buy **three website-brand domains** (`getaspiredwebsites.com`,
`goaspiredwebsites.com`, `tryaspiredwebsites.com`, or whatever is free).
~$36/year. Three mailboxes each = 9 mailboxes = 270 sends/day.

**The 2–3 week warming period is not a delay** — there is nothing worth
sending until the list problem is fixed, and that takes about as long.
The timelines line up. Start the domains today so the clock runs in the
background.

Keep the Automations mailboxes for Automations.

## Volume math for the stated goal

Goal: **5–6 clients/month.** With a good list (named decision-makers,
bounce-verified, one specific true observation per email):

```
1,000 emails → ~40 replies (4%) → ~11 positive → ~6 calls → ~2 clients
```

| Target | Emails/mo | New contacts/mo | Mailboxes @ 30/day |
|---|---|---|---|
| 5–6 clients | 3,000–4,000 | 800–1,000 | 8–10 |

Monthly cost:

| Item | Cost |
|---|---|
| Contacts (~1,000 @ $0.0022) | ~$2 |
| Bounce verification | ~$3 |
| 3 domains | ~$3 |
| Instantly | ~$100–150 |
| **Total** | **~$110–160/mo** |

Lead supply costs essentially nothing. Sending infrastructure is the
only real line item.

### The caveat that matters

**Every current client came from a referral, friend, or family.** The
offer has never been sold to a stranger. That's a fundamentally different
sale — referrals arrive pre-trusted.

**Month one's goal is 5 booked calls, not 5 closed clients.** Prove the
offer converts cold, then scale the machine — which is already largely
built.

### On the waitlist-with-a-discount idea

Flip it. Discounting to manage overflow teaches prospects to wait for a
discount and permanently lowers the anchor. When overloaded, raise the
price or extend the timeline. Scarcity is already the incentive.

## The process, stage by stage

### 1. SOURCE — person-level, not business-level

Replace Google Maps as the primary source. Maps gives a *business*
(→ `info@`); an Apollo-style database gives a *named partner*
(→ `sarah@`). That substitution is the fix.

**Criteria:** TX + GA · 1–20 employees · titles = Owner, Partner,
Managing Partner, Principal, Founder · **one niche at a time**.

**Blocker:** the actor refuses API runs on the free Apify plan. Options:

- **Free path (start here):** run it in the Apify UI, paste the dataset
  ID into Django. `import_from_dataset()` is already built and dataset
  reads are free.
- **Paid path:** Apify Starter ~$49/mo unlocks API runs, which is what
  Prospect needs to run unattended.

### 2. VERIFY — this stage does not exist and is the root cause

Two rules, both non-negotiable:

**Suppress role addresses before sending.**
`info@ office@ admin@ contact@ hello@ sales@ support@ team@ inquiries@`
Those 135 sends should never have left the building.

**Bounce-verify every address** — MillionVerifier / ZeroBounce,
~$0.001–0.004 each. Reject `invalid`, `unknown`, **and `catch-all`**.
Under $4/month at this volume. Above a 3% bounce rate Google and
Microsoft begin filtering, and no amount of warming undoes it.

### 3. ENRICH — mostly built; one thing off, one thing fixed

`enricher.py` already computes PageSpeed, HTTPS presence, and copyright
year. That is the *specific true observation* cold copy needs — the
difference between "your site looks dated" and "your intake form posts
over plain HTTP."

- **Turn off** the page email-scraping path once the database supplies
  emails. It is what produced `rohtopharmacy5@`.
- **Fix** `_web_search_fallback` — it takes the first `facebook.com`
  search hit with no verification. Measured wrong ~50% of the time this
  session. **Currently live on prod.**

### 4. SEGMENT — one campaign per niche × state

Four to start: TX law, GA law, TX dental, GA dental. Copy that
references a real detail cannot be written for a blended list, and
per-campaign reply rates are how you learn which niche actually wants
this.

**Niche note:** the CISSP + Masters is worth most where security is a
*legal obligation*, not a preference — medical/dental (HIPAA), law
(confidentiality and bar ethics rules on electronic communication),
CPAs and financial advisors (IRS Pub 4557, SEC/FINRA). Everyone else in
that inbox is leading with "modern design."

### 5. SEQUENCE — an architecture fork to decide

**Django sends (today):** `dispatcher.py` → SendGrid. One domain, no
rotation, no warmup. Fine at 10/day, fatal at 300.

**Instantly sends (recommended):** Django stays the brain — source,
verify, enrich, score, write copy — and pushes contacts to Instantly.
Instantly owns mailbox rotation, warmup, throttling, bounce handling.
That is what it is being paid for and the only way 270/day survives.

Guardrails, variant rotation, the approval queue and spend caps all live
on the Django side and keep working either way.

Four touches, stop on reply, CAN-SPAM postal address and unsubscribe on
every send.

### 6. REPLY — bug fixed, ingest filter still missing

The `classifier.py` import bug is fixed, so reply drafts will generate
for the first time. But the 10 junk rows prove the **ingest** has no
filter — it took Google Ads notifications and labelled them
`wrong_person` rather than recognising they are not replies at all.

Needs: drop mail from our own domains; drop `no-reply@`, `bounce@`,
`mailer-daemon@`; match against a real `EmailSent` thread before
creating an `EmailReply`. If replies arrive via Instantly this becomes a
webhook instead of IMAP, which is cleaner.

### 7. BOOK — exists, never exercised

Scheduler and `record_booking` are wired (`confirm_slot` hookup done
this session). Neither has seen a real booking. The first one will find
bugs.

   Facebook bug.

7. **Send 200. Measure.** Only then scale toward 1,000/month.
