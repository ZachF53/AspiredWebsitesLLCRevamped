{% comment %} The booking POSTs are fetch() calls, not a form submit, but the token has to reach the page somehow: CSRF_COOKIE_HTTPONLY is True, so document.cookie can never see it. schedule_call.js reads this hidden input instead. method="post" is load-bearing even though the happy path never uses it. A with no method defaults to GET, so any submit that reaches the browser — JavaScript failing to load, a script error, Enter pressed in a text field before the handler binds — put the visitor's name, email, phone and project description into the URL. From there they reach server logs, the Referer header and analytics, which is not somewhere prospective-client details should ever be. POST keeps them in the request body, and the view answers that submit with a clear message rather than silently discarding it. {% endcomment %} {% csrf_token %}
